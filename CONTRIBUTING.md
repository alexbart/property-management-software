
# Contributing

## Branches

- main: Production-ready
- feature/*: Feature development
- fix/*: Bug fixes
- docs/*: Documentation

## Commits

Follow Conventional Commits.

Examples:

- feat(properties): add property registration
- fix(payments): prevent duplicate callbacks
- docs(architecture): update database design
- test(arrears): add penalty boundary tests

## Pull Requests

Every pull request should include:

- Summary of changes
- Affected modules
- Database changes
- Tests performed
- Known limitations

All relevant CI checks must pass before merging.

Never commit secrets or real tenant data.
